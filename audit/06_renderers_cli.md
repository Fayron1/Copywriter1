## 1. 🔴 Находки

### 1.1. `autofix_gate`: правило «30 дней → пять дней» создаёт ложную норму в готовой статье

**Место:** `autofix_gate.py:32–36`, слой 1, применяется **к финальным файлам** (fix_dir пишет md/txt/html на диск).

```python
(re.compile(r"не\s+позднее\s+30\s*(?:календарн\w+\s*)?дн\w+", re.I),
 "не позднее пяти дней",
 re.compile(r"59-ФЗ|обращени\w+\s+граждан\w*|...", re.I),   # единственный гард
 ...)
```

Гард-окно ±200 симв. проверяет только маркеры 59-ФЗ. Любое легитимное «не позднее 30 дней» **без** упоминания 59-ФЗ молча переписывается в «не позднее пяти дней»: например «запрос документов — не позднее 30 дней», «возврат переплаты не позднее 30 дней» (у правила про 10 дней гард «подпис|возврат|обеспечени|таможен|транзит» есть, у 30-дневного — нет). Это прямой инъектор неверной правовой нормы в публикацию, работающий **после** всех валидаций, — самый опасный модуль этапа.
**Фикс (направление):** сузить паттерн до связки «жалоб|обжалова|протокол» в окне; перенести правило из AUTOFIXES в детектор (🔴) без автозамены; почистить правила-патчи статьи 26 (см. §3.3).

### 1.2. `deliverables`: тихая потеря контента пакета на линтер-фильтре

**Место:** `deliverables.py:304, 316, 322, 329` — `not lint_legal(...)` как булев фильтр **без логирования**.

Мета/FAQ/TC-посты/анонс, получившие любой issue от `lint_legal` (включая подтверждённые в этапе 3 ложные срабатывания: 🔴 НЕЗАПОЛНЕННЫЙ ШАБЛОН на markdown-ссылки `[ФНС](url)` в TG-постах, 🔴 ПРОМПТ-ЛИК на «Исправьте…» в FAQ), **молча выбрасываются** из пакета. Симптом: «пакет собран: FAQ 2, TG-посты 1» вместо 5/3 без объяснения. Отладка поставки невозможна.
**Фикс (направление):** логировать отбраковку (какой маркер, какой текст); фильтровать только 🔴, а 🟡 — пропускать с пометкой.

### 1.3. Паспорт источников: `high_risk_claims` всегда пуст — рассинхрон контракта claim-леджера

**Место:** `deliverables.py:110–115` против `claim_ledger.py:105–120`.

`build_source_passport` читает `c.get("type")` и `c.get("claim")`, а claims пайплайна имеют ключи **`claim_type`** и **`text`**. Условие `c.get("type") in ("legal_rule","calculation")` — всегда False → раздел паспорта `high_risk_claims` (топ-10 юридически рискованных утверждений — то, ради чего паспорт существует) **всегда пуст**. Ни ошибки, ни лога — тихая потеря ключевого содержимого поставки.
**Фикс (направление):** `c.get("claim_type")` / `c.get("text") or c.get("claim")`.

## 2. 🟡 Средний приоритет

### 2.1. `factcheck`: наблюдения-маркеры выводят числа из-под фактчека

`factcheck.py:556–574`: утверждение, содержащее «обычно» / «на практике» / «чаще всего» / «большинство», помечается supported **целиком** — вместе с любыми числами в нём. Выдуманная цифра в предложении с «обычно» не хеджируется никогда. Исключение задумано для защиты авторских оценок, но сделано пословно, а не по охвату (маркер должен спасать саму оценку, не соседнюю цифру). Плюс «на моей практике» тут же ловит 🔴 ПСЕВДО-ЭКСПЕРТ у линтера — система борется сама с собой.

### 2.2. `factcheck`: схлопывание безразмерных чисел

`factcheck.py:470–481`: `_normalize_value` отбрасывает единицы — «5 дней», «5 млн», «5%» (без знака) дают одно значение «5». Матчинг «supported по значению» может подтвердить выдуманное «5 дней» фактом про «5 млн». Годы и номера статей замаскированы (`_CITATION_MASK_RE`), единицы измерения — нет.

### 2.3. `build_seo_title` режет заголовок по первому двоеточию

`deliverables.py:55`: `re.sub(r"\s*[—:|].*$", "", base)` — SEO-титул из H1 «НДС 22%: как снизить нагрузку» → «НДС 22%». Заголовки с двоеточием — норма для B2B; хвост-крючок теряется в `seo_title` контент-пакета (и в HTML `<title>` при фолбэке). Скорее всего задумывалось только для тире-подзаголовков.

### 2.4. `generate.py`: подстановки в HTML-шаблон по цепочке `.replace`

`generate.py:929–938`: `{html_body}` вставляется 4-й подстановкой, затем последующие `.replace("{date}", ...)` и др. применяются **по всей строке, включая тело статьи**. Литерал `{date}`/`{keywords_html}` в тексте статьи (технические темы с примерами кода/f-строк) будет подменён служебными значениями в HTML. Для текущих доменов редкость, но механизм хрупкий — безопаснее единственный маркер-протокол как в deliverables (`@@EXCERPT@@`).

## 4. Что проверено и чисто

- **`jev_client.py`** — образцовый модуль: таксономия ошибок по статусам, ретраи строго по контракту (429 + Retry-After, 502/503 bounded, 504 — один), лимит тела 256 КБ, ключ не логируется, graceful degradation (`get_jev_client` → None). Используется роутером (и мёртвым virality_engine — см. этап 2 §3.7).
- **`cta_renderer.py`** — полностью детерминирован: verified-факты профиля, запрет абсолютов с дублированием линтером, суб-маршрутизация ВЭД/маркетплейсы, доменный фолбэк generic, защита от двойной вставки по якорю, editorial-режим → None.
- **`html_and_entities.py`** — required-сущности (24/72ч при утечках, порог НДС на УСН, взносы ИП «за себя/за работников») с per-domain гвардами; validate_html (таблицы/якоря/LaTeX) — корректно.
- **`factcheck.py`** — все четыре верификатора (verify_facts, validate_law_references, check_future_laws, hedge_*) построены единообразно: детерминированное извлечение → один grounded вызов → жёсткие программные фильтры (≥2 источника из ≥2 доменов; confidence ≥0.75 для будущего; «если unsure — correct» против ложных wrong_topic); маскировка цитирований от ложного supported по номерам статей; при любом сбое — пусто, пайплайн не падает.
- **`_call_kie_generic`** — ретраи только 429/5xx, backoff 2^attempt cap 10, невосстановимые коды — сразу None.
- **Контракты**: `humanize_article(text, split_fn, reassemble_fn, rewrite_fn, min_score, max_fix, editable_levels, logger)` ↔ вызов из pipeline:4008 ✓; `freshness.check_facts(facts) → (dict, list)` ✓; `ArticleRouter.route(...)` ✓; все таймауты vane/searxng на месте.
- **`generate.py`** — CLI полный: ключи проверяются до старта, Qdrant недоступен → RAG отключается намеренно (контракт с rag.py:80 соблюдён), SEO-гварды keyword-фантомов и мета-цифр, publish-gate в passport.txt с PUBLISH_ALLOWED.
