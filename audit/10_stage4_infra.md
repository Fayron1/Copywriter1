## 1. Находки

### 🟠 K1 (высокий). `/gen` в боте доставляет статью дважды, второй экземпляр — без гейта
**Цепочка (проверена по коду):**
1. `kb_update.py:49–50` грузит `.env` → в процессе есть `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.
2. `_generation_worker` (kb_update.py:178): `cmd = [generate.py, topic, "--chars", "8000", "-p", "deepseek"]` — **без `--no-send`**, env наследуется (`dict(os.environ)`).
3. generate.py:1424–1426: при обоих env-переменных запускает автоотправку → `send_article_to_bot` → **гейт-проверенный** архив №1 уходит в чат.
4. Воркер после завершения генерации собирает **свой** ZIP (kb_update.py:181–191) и шлёт его же — **архив №2, мимо гейта** (`fix_dir`/`gate` в этом пути не вызываются вовсе — grep по kb_update.py: 0 упоминаний).

**Эффект:** чат получает два архива на каждый `/gen` (проблема «нескольких зипов» из кейса 26 возвращается), причём второй — без финального контроля 🔴. Если `TELEGRAM_CHAT_ID` в .env на VPS отсутствует, шаг 3 пропускается и двойной отправки нет — но тогда и гейт не применяется ни к одной копии.
**Рекомендация (одно из двух):**
- добавить `--no-send` в cmd воркера и **встроить гейт в путь воркера** (`from agents.autofix_gate import autofix, gate` перед сборкой ZIP — код готов, send_article_to_bot показывает как); или
- убрать собственный ZIP из воркера и доверить доставку автоотправке generate.py, воркеру оставить только доклад «готово/ошибка».
