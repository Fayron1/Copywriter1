## 2. Находки по новому коду (этап 2)

### 🔴 N1. ADMIN_FINE_FORMULA_LOCK блокирует публикацию налоговых статей
**Где:** `norm_params.py:2788–2794` (паттерн), интеграция `lint_regulation_layers` ← `lint_marketing_growth` (2643–2644) ← `lint_legal` (2527) — выполняется на **всех** доменах.
**Суть:** линтер ревью-35 написан под ВЭД-тему, но третий альтернативный паттерн `(?:штраф|санкци\w+|риск\w*)[^\n]{0,120}\d[\d\s]{5,}\s*(?:руб|₽)` ловит **любую цитату фиксированного штрафа**. Маркеры `_FINE_OK` («действующей редакции», «зависит от конкретной части», «КоАП») не знают про налоговый контекст.
**Живое подтверждение (прогон линтеров в памяти):**
- «штраф … минимум 40 000 рублей по ст. 122 НК РФ» → 🔴 ADMIN_FINE_FORMULA_LOCK
- «Штраф для организации составит 100 000 ₽ согласно п. 1 ст. 119 НК РФ» → 🔴

**Эффект:** `send_article_to_bot.py:54–65` на любом 🔴 делает `SystemExit(1)` → легитимная налоговая статья не уйдёт в бот после генерации; в generate.py напечатается «Отправка в бота не прошла». Регресс не ловит: налоговых фикстур для новых линтеров нет (213 тестов — про свои кейсы).
**Рекомендация:** в `_FINE_OK` добавить маркеры цитаты нормы НК/КоАП (`ст\.\s*\d+`, `НК\s+РФ`, `гл\.\s*16`) либо сузить `_FINE_FORMULA` до расчётных формул (`1\s*/\s*150`, `%\s*/\s*150`, «складывается») и диапазонов с двух сторон, а не любых сумм ≥6 знаков. Плюс — добавить в регресс 2–3 налоговые фикстуры на новые линтеры (кросс-доменный тест).

### 🟡 N2. Фикс 🟡17 применён наполовину: expiry check всё ещё мёртв
**Где:** `kb_update.py:405` — `flt = Filter(must=[FieldCondition(key="valid_until", range=rng)])`; импортируется только `from qdrant_client import models` (394). `Filter`/`FieldCondition` как имена не существуют → NameError → глотается `except Exception` (411) → «expiry check сбой: …» каждый день.
**Рекомендация:** `models.Filter(must=[models.FieldCondition(...)])`. Одна строка.

### 🟡 N3. Claim pack отстаёт от коррекций верификатора
**Где:** `pipeline.py:1093–1095` (pack собирается в конце `_step_fact_finder`) vs `pipeline.py:1216–1242` (`_step_fact_verify` правит `fact["claim"]` в `state.facts` **после** сборки pack).
**Суть:** Heart получает исправленную версию через «ФАКТЫ» и старую — через claim pack (вклеен в rag_block, 1662–1664). Два источника могут противоречить друг другу; «верификатор — уточнить» из комментария в claim_ledger фактически не доезжает.
**Рекомендация:** после блока коррекций в `_step_fact_verify` перестроить claims/pack (`extract_claims` + `build_claim_pack` на скорректированных facts) — это дёшево, 0 API-вызовов.

### 🟡 N4. Статейные автофиксы с `guard=None` глобальны
**Где:** `autofix_gate.py` (волна «Ревью 28»): «закупках по 223-ФЗ» → «по 44-ФЗ»; «меры не применяются» → развёрнутый закупочный текст; ещё 5 патчей из ревью 27v3/28.
**Суть:** патчи писались под конкретную статью, но применяются к любой будущей. Статья, честно пишущая про 223-ФЗ, будет молча переписана в 44-ФЗ на финальном гейте. Ирония: параллельно добавлен линтер SCOPE_OF_CHANGE ровно про такую подмену охвата.
**Рекомендация:** для статейных патчей — либо guard по теме/домену (третий элемент кортежа), либо перенос в `gate_markers.json` рядом со статьёй (механизм `required_absent/required_present` уже поддержан гейтом). Универсальные патчи (оборванное «однако», «Смарта») можно оставить.

- **section_index 0-базный** в каталоге ревизора `[0] (вступление)`, `[1] H2…` — bounds-чек `0 <= idx < n_sections` консистентен; `int(idx)` конвертируется до фильтра.

- **Heart overshoot:** `heart_aim = int(target_chars * 0.85)` — min/max в инструкции не занижены, режется только «идеал» — логика корректна.
- **Auto-send env-гейт:** отправка стартует только при наличии `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`, `--no-send` есть, сбой не валит генерацию, timeout 300 c.
