## 1. 🔴 КРИТИЧНО: `enforce_params` теряет единицу измерения при замене по паспорту

**Место:** `norm_params.py:366–371` (ветка «число с единицей»).

```python
if unit:
    for needle in (f"{num}{unit}", f"{num} {unit}", f"{num}\u00a0{unit}"):
        if needle in text:
            text = text.replace(needle, cur_first)   # ← cur_first = ТОЛЬКО число
```

`cur_first` — это **первое число** из `value` паспорта, извлечённое регэкспом `\d[\d\s.,/]*` (строка 359). Единица (`%`, `млн`, `руб`) из `value` в замену **не попадает**.

**Живое воспроизведение (проверено кодом):**

```
Вход:  «На ОСНО компания платит НДС по ставке 20% с вычетами, порог 60 млн.»
Паспорт: value='22%', old_value='20%' | value='20 млн', old_value='60 млн'
Выход: «На ОСНО компания платит НДС по ставке 22 с вычетами, порог 20.»
FIXES: ['20% → 22 (ставка НДС)', '60 млн → 20 (порог НДС УСН)']
```

- Это **флагманский сценарий системы** (замена 20%→22% — пример прямо в промпте экстрактора `EXTRACT_SYSTEM`, строка 64). Каждая статья со строгой темой, где LLM вернул `old_value` в форме с единицей, получает в тексте «ставка НДС 22» без процента.
- Механизм создан, чтобы **убирать** числовые ошибки, а производит их: «порог 20» вместо «20 млн» — фактическая дезинформация в публикации.
- **Почему 160/160 зелёные:** диспетчер тестов вызывает `enforce_params(text, None, article_year=2026)` (`regression_tests.py`, checker `legacy`) — с `params=None` паспортная ветка не выполняется вовсе. Тестируется только `_LEGACY_VALUES`-путь, где замена делается на `current["replacement"]` = «20 млн»/«22%» (с единицей, корректно). Паспортная ветка **не покрыта ни одним тестом**.
- **Почему прод «держится»:** видимо, спасает то, что `_LEGACY_VALUES` (тоже выполняется при каждом вызове) успевает заменить типовые «60 млн»/«20%» корректно ещё до/после паспортного прохода в текстах без паспорта; при живом паспорте баг срабатывает.
- **Направление фикса:** в ветке `unit` заменять на полную форму из value с сохранением единицы (`cur_first` + `unit` при его отсутствии, либо парсить value парой «число+единица» через `_num_unit_pairs`); добавить регресс-тест с паспортом (`params=[{...value:'22%', old_value:'20%'}]`).

**Пара к фиксу:** та же ветка не проверяет соответствие единиц `old_value` и `value` (замена «60 млн» → «20» при value «20 млн» — потеря «млн»; а при value «до 240 часов» кейс 23 уже был частично учтён комментарием в коде, но только для голых чисел).

## 2. 🟡 Средний приоритет

### 2.1. Псевдо-экспертные автозамены ломают грамматику — `norm_params.py:383–399`

**Проверено кодом:**

```
Вход:  «На моей практике как юриста это частая ошибка при переходе.»
Выход: «при аудите подобных систем юриста это частая ошибка при переходе.»
```

Замена «на моей практике как» → «при аудите подобных систем» оставляет висячий творительный «юриста». Последующие замены (`("как юрист", "")`) срабатывают только по точной подстроке «как юрист», а не «юриста». Результат уезжает в статью **безусловно** (pipeline.py:748 применяет фиксы к тексту без пере-линта грамматики). Аналогичный риск: `("налоговый консультант,", "специалисты,")` — запятая вшита в паттерн.
- Направление фикса: паттерны целыми словосочетаниями с падежами (`на моей практике как юрист[ауеи]\w*` → нейтральная полная фраза), либо после замены прогонять `lint_legal` повторно.

### 2.2. `_PROMPT_LEAK`: ложные 🔴 на легитимных советах — `norm_params.py:1260–1264`

**Проверено кодом:**

```
«Исправьте декларацию до 25 числа»  → матч «Исправь»      → 🔴 ПРОМПТ-ЛИК
«Сгенерируйте отчёт за квартал»     → матч «Сгенерируй»   → 🔴 ПРОМПТ-ЛИК
```

Паттерны `исправь|сгенерируй|перепиши` без границ слова матчат вежливые повелительные в **содержании статьи** («исправьте ошибку в декларации» — штатный совет в налоговых чек-листах). Эффект в конвейере: `lint_legal` вызывается из `check_draft` → `_validate_final` (pipeline.py:718, 4759); 🔴-маркеры попадают в `red_errors` → Heart **трижды переписывает черновик** (pipeline.py:1743–1754), безуспешно пытаясь убрать легитимные слова, затем «оставляем последний вариант» + красные флаги в publish-gate.
- Направление фикса: границы слова (`\bисправь[те]?\b` всё равно матчит «исправьте»...) — правильнее убрать из перечня `исправь/сгенерируй/перепиши` и оставить многословные, заведомо служебные конструкции («вот черновик», «вот несколько вариантов», «редактура:»), либо проверять, что фраза стоит на отдельной строке/вне кавычек-советов.

### 2.3. `_UNRESOLVED_TEMPLATE` матчит markdown-ссылки — `norm_params.py:1006–1009`

**Проверено кодом:** `\[[а-яё\s]{2,20}\]` срабатывает на `[ФНС](https://fns.gov.ru)`, `[Источник](url)`, а также на легитимные вставки вида `[Приложение]`.

- В основной волне валидации это ещё не стреляет (блок «Источники» собирается **после** `_validate_final`, pipeline.py:880 vs 718). Но `lint_legal` выполняется также в `deliverables.py:304/316/322/329` на выходах паковщика (TG-посты содержат ссылки) и в `autofix_gate.py:190`. Ложный 🔴 отбраковывает корректный пост/фрагмент паковщика молча (просто не включается в пакет).
- Направление фикса: `\[[а-яё\s]{2,20}\](?!\()` — не матчать начало markdown-ссылки; для `[Приложение]` — список whitelisted слов.

### 2.4. `lint_year_rules`: хрупкая эвристика сокращённой формы — `norm_params.py:112–121`

`short_form` использует **первое** попавшееся «N млн» во всём тексте и сравнивает префиксы с обрезками `lstrip("0")`/`[:3]`; `short_match` через `int(n[:len(n)-6])`. Логика рабочая для единственного правила (2027: порог 20 млн → 15 млн), но:
- ложное срабатывание возможно, если статья 2027 года упоминает «20 млн» в историческом контексте («до 2026 действовал порог 20 млн») — упоминание легитимно, а правило требует отсутствия значения 2027 в паспорте, не в тексте;
- при добавлении второго правила в `KNOWN_FUTURE_RULES` эвристики не обобщаются (хардкод «млн»).
- Направление фикса: заменить префиксную магию на явную проверку «число из old-порога + единица» через `_num_unit_pairs`, как сделано в `check_draft`.

## 4. Тестовый набор — оценка качества защиты

**Сильные стороны:**
- 160 тестов, формат «(имя, вход, ожидаемый маркер, функция)» — прямое соответствие «ошибка статьи → правило».
- Есть **негативный контроль** (`lint_neg`): список новых маркеров не должен срабатывать на чистом тексте — правильная дисциплина.
- Покрыты все классы исторических ошибок редактора: устаревшие значения, числовые артефакты, псевдо-эксперт, заглушки статей, форма/срок/ПСН, квартал-vs-месяц, КЭДО-подписи, ГПХ-этика, прогнозы-как-факты, обрывы.
- Тест `bare_year` — защита от порчи годов (кейс «2026» → «22/12226») — покрыт.

**Дыры покрытия:**
1. **Паспортная ветка `enforce_params` не тестируется вообще** (checker `legacy` зовёт с `params=None`) — из-за этого критичный баг §1 невидим. Один тест с `params=[{"params":[{"value":"22%","old_value":"20%"}]}]` поймал бы.
2. Ложные срабатывания не тестируются в негативе для `_PROMPT_LEAK` («Исправьте...») и `_UNRESOLVED_TEMPLATE` (ссылки) — оба подтверждены живым прогоном.
3. `check_matrix_compliance` / `fix_matrix_violations` (LLM-функции) — вне тестов естественно, но объёмная защита `0.8 ≤ len/len ≤ 1.25` в fix (строка 527) хороша.

## 5. Что проверено и чисто

- `_num_unit_pairs` / `_in_text`: исключение годов (19xx/20xx), различение единиц («20%» ≠ «20 млн»), варианты запятой/точки — корректно.
- `check_draft`: сверка old→текст через `_in_text` с единицами, «missing»-предупреждения ограничены 3 шт. — корректно.
- `check_matrix_compliance` / `fix_matrix_violations`: LLM-вызовы обёрнуты, фиксы защищены проверкой объёма (0.8–1.25), температурный режим разумный.
- `fix_table_of_contents`: перегенерация из реальных H2, guard `has_list`, исключение «Содержание»/«Источники» — корректно.
- `detect_truncation`: отсечение хвостовых блоков (Источники/Примечания) до поиска обрыва, три признака обрыва — логика корректна.
- ~60 новых правил из «Ревью 20–26» (валютный домен, закупки 44/223-ФЗ, маркетплейсы, сверхурочные 240ч, КЭП-противоречия): окна контекста ±150–400 симв., белые списки `_OK`-регэкспов, маркеры моделей `_MODEL_MARKER` как exemption — архитектура правила единообразная и разумная; грубых катастрофических регэкспов (backtracking) не выявлено — квантификаторы ограничены (`[^.\n]{0,N}`).
- Прогон всего набора: **160/160** — воспроизведён.
