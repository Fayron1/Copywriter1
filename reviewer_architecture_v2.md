# Ревизор v2 — архитектура после аудита (2026-10-06)

## Что изменилось после аудита

Аудит выявил: главный риск — не модель, а управляющая логика. Высокий балл обходит
запрет публикации, Accept-Best возвращает небезопасную версию, одобренный раздел
считается неприкосновенным даже после изменения контекста.

## Три прохода вместо одного

### Проход A: Evidence Auditor
Проверяет, подтверждает ли доказательство именно опубликованную формулировку.
upstream_status — подсказка, не доказательство. VERIFIED допустим только при
установленном соответствии текста источнику. Проверять не просто наличие цитаты,
а не расширен ли смысл: «штрафы» → «вся неустойка», «закупка для СМП» → «любая МСП».

Вход для каждого значимого утверждения:
```
claim_id, article_quote, source_url, source_excerpt,
source_fragment_type (normative_text/annotation/court/official),
checked_at, effective_from, effective_until,
subject, regime, conditions, exceptions, upstream_status
```

### Проход B: Article Integrity Auditor
Проверяет отношения между фрагментами. Самый важный недостающий слой.

finding_type:
- CROSS_SECTION_CONTRADICTION (таблица против абзаца)
- CALCULATION_INTERPRETATION_ERROR (расчёт верен, вывод неверен)
- MISSING_PROMISED_CONTENT (заголовок обещает, текст не раскрывает)
- MISSING_EXCEPTION (правило без исключения)
- SOURCE_MISMATCH (источник не подтверждает вывод)
- UNSUPPORTED_PRACTICE_CLAIM (псевдопрактика)
- PATCH_REGRESSION (старая ошибка осталась после патча)

### Проход C: Reader-value Judge
Запускается ПОСЛЕ закрытия содержательных блокеров. Оценивает:
- Какое решение читатель может принять после чтения?
- Где показана развилка?
- Когда совет НЕ подходит?
- Полезный результат помимо пересказа источников?

Шаблонность → Mirror/Humanizer. Ревизору передавать их результаты, только если мешают пониманию.

## Контракт правок

Каждая правка с критерием закрытия:
```json
{
  "issue_id": "VAT_TOTAL_001",
  "severity": "BLOCKER",
  "finding_type": "CALCULATION_INTERPRETATION_ERROR",
  "locations": [
    {"block_id": "example_01", "quote": "Итог к уплате — ноль"},
    {"block_id": "mistake_02", "quote": "по правилам должна выйти на ноль"}
  ],
  "operation": "REPLACE",
  "instruction": "Разделить налог по сделке и дополнительный налог при отгрузке.",
  "acceptance_criteria": [
    "Общий НДС указан как 5000 рублей.",
    "Нулевой результат только для дополнительного начисления.",
    "Все связанные повторы исправлены."
  ]
}
```

Идентификация: section_id + block_id + text_hash (не section_index — меняется при вставках).
Если место правки не определено однозначно → технический отказ применения патча.

## Матрица публикации

| Статус | Действие |
|---|---|
| VERIFIED | Разрешить при наличии доказательства |
| VERIFIED_WITH_LIMITS | Проверить, отражены ли ограничения |
| UNSUPPORTED | Найти доказательство или удалить |
| CONTRADICTED | Исправить или удалить |
| OUTDATED | Обновить источник и текст |
| NEEDS_HUMAN_REVIEW | Не выпускать автоматически |

## Порядок конвейера

```
Heart → Claim Check → Evidence Auditor → Integrity Auditor
  → исправления → проверка закрытия → Booster → Packager
  → Final Integrity Gate → публикация
```

Final Integrity Gate (после Booster/Packager): проверять только
изменённые/добавленные утверждения, заголовки, FAQ, выводы,
соответствие производных материалов утверждённым claims.

## Критерий публикации

```python
publishable = (
    review_complete
    and claim_coverage_complete
    and not open_blockers
    and not open_mandatory_edits
    and required_gates_passed
    and final_artifact_verified
)
if publishable and editorial_score >= editorial_threshold:
    break
```

Если после 3 итераций нет publishable версии:
```
publication_status: NEEDS_HUMAN_REVIEW
draft_available: true
unresolved_issues: [...]
```

## Исправление Claim Check

Не хеджировать неподтверждённое — это маскирует отсутствие проверки:
- Подтверждено → оставить
- Подтверждено при условиях → явно написать условия
- Не подтверждено → найти доказательство, удалить или эскалировать

Оговорки — для реальной условности, не для маскировки отсутствующего доказательства.

## Тестовый набор

30–50 коротких фрагментов + несколько полных статей:
1. Ошибка в гарантии только в таблице
2. Спецштраф привязан к статусу МСП (не к виду закупки)
3. Списание обещано, но отсутствует
4. НДС при отгрузке нулевой, а по сделке — нет
5. Возврат аванса пропущен как основание вычета
6. Корректное условное утверждение (нельзя блокировать)
7. Правильный текст без проблем (нельзя блокировать)
8. Источник существует, но не подтверждает вывод
9. Исправленная версия, где старая ошибка осталась в FAQ

Метрики: пропуск блокеров, ложные блокировки, покрытие, закрытие
исправлений, регрессии, стабильность, стоимость.

## API: gpt-6-1-sol через KIE

Endpoint: `POST https://api.kie.ai/codex/v1/responses`
Формат: `input` (не messages), `reasoning.effort`, `output[]` (не choices).
Требует отдельной проверки: structured output, web search, reasoning effort,
полнота ответа, парсинг ошибок. Ошибка → REVIEW_INCOMPLETE, не молчаливое одобрение.

## Порядок внедрения

1. Убрать выход по score>=90 (небезопасный Accept-Best)
2. Дать Ревизору доказательства (source_excerpt, не только status)
3. Внедрить проверку межфрагментных противоречий (Integrity Auditor)
4. Разделить Claim Check: хедж → эскалация/удаление
5. Ввести независимое закрытие замечаний (критерий закрытия + проверка)
6. Финальный гейт после Booster/Packager
7. Собрать тестовый набор → сравнивать модели на одном наборе
